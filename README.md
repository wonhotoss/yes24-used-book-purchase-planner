# yes24 중고책 구매 계획기

사고 싶은 중고책 목록을 넣으면 yes24 중고샵의 판매 건을 모두 모읍니다. 그다음 **책값과 판매자별 배송비를 더한 총액이 가장 작은** 구매처 조합을 계산해 마크다운 보고서로 냅니다.

중고책은 판매자마다 배송비가 따로 붙고, "N원 이상 구매 시 무료배송" 같은 조건도 판매자마다 다릅니다. 그래서 책마다 최저가를 고르는 방법이 늘 가장 싸지는 않습니다. 조금 비싼 책이라도 한 판매자에게 몰아 사서 배송비를 한 번만 내거나 무료배송 기준을 넘기는 편이 쌀 때가 많습니다. 이 도구는 그 조합을 정수계획(MILP)으로 정확히 풉니다.

```
목록(제목·ISBN) → 중고샵 검색 → 판매 건 수집 → MILP 최적화 → 보고서 (→ 카트 대조)
```

## 결과 예시

| 목록 | 최적 계획 | 책마다 최저가로 따로 살 때 |
|---|---|---|
| 개발서·교양서 8권 ([보고서](examples/sample-plan.md)) | **96,000원** · 주문처 4곳 | 101,790원 · 8곳 (5.7% 절약) |
| 처음 읽는 그리스 로마 신화 10~12권 ([보고서](purchases/2026-10-05-greek-myth/plan.md)) | **35,650원** · 1곳 | 40,150원 |

두 번째 건은 실제로 구매했습니다. 카트에 담아 확인한 결제 금액이 계획과 같았습니다.

## 설치

Python 3.10 이상이 필요합니다.

```
pip install -r requirements.txt
playwright install chromium      # 카트 대조(--verify-cart)를 쓸 때만
```

최적화 솔버는 PuLP에 포함된 CBC를 씁니다. 따로 설치할 것은 없습니다.

## 사용법

### 1. 목록 파일 만들기

한 줄에 책 한 권을 씁니다. `#`으로 시작하는 줄은 주석입니다.

```
# 개발서
클린 코드 인사이트
9788966260959
데미안 = 176787 8156036
처음 읽는 그리스 로마 신화 10
```

| 줄 형태 | 뜻 |
|---|---|
| `클린 코드 인사이트` | 검색어. 중고샵 검색 1순위 판본을 씁니다 |
| `9788966260959` | ISBN도 검색어로 통합니다 |
| `데미안 = 176787 8156036` | 판본 고정. `=` 뒤 상품번호 중 어느 판본이든 삽니다 |
| `… 신화 10` | 시리즈는 권 번호를 검색어에 넣습니다 |

상품번호는 yes24 상품 페이지 주소 `/product/goods/{번호}`의 숫자입니다. 줄 중간의 `#`은 주석으로 처리하지 않으니 설명은 따로 한 줄로 씁니다.

### 2. 실행

```
python -m ubc list.txt -o plan.md
```

자주 쓰는 옵션:

| 옵션 | 뜻 |
|---|---|
| `-o plan.md` | 보고서 파일. 판매 건 스냅숏(`plan.offers.json`)도 같은 이름으로 저장 |
| `--min-grade 상` | 이 등급 이상만 (최상·상·중·하, 기본 하) |
| `--min-rating 4` | 판매자 만족도 이 점수 이상만 |
| `--exclude 판매자ID …` | 특정 판매자 제외 |
| `--cache .cache` | 받아 온 HTML을 저장해 같은 날 다시 돌릴 때 재요청하지 않음 |
| `--verify-cart` | 계획대로 **비회원 카트**에 담아 yes24가 계산한 금액과 대조하고 스크린숏(`plan.cart.png`)을 남김 |

### 3. 보고서 읽기

- **구매 계획**: 판매자별로 살 책, 책값, 배송비, 총액
- **비교 기준**: 책마다 따로 최저가로 샀을 때의 총액과 절약액
- **등급 조건별 최적 총액**: 하·중·상·최상 이상으로 제한할 때 각각의 총액. 등급을 올리면 얼마가 더 드는지 보여 줍니다
- **판본**: 책마다 검색 후보(상품번호·제목·출판사·판매 건 수)와 실제로 쓴 판본. 판본이 틀렸으면 목록에서 `= 번호`로 고정해 다시 돌립니다
- **카트 대조**(`--verify-cart`): 상품금액·배송비·최종 결제금액이 계획과 맞는지

### 4. 구매

보고서대로 yes24에서 직접 담아 결제합니다. 이 도구는 주문이나 결제를 하지 않습니다. 카트 대조도 매번 새 브라우저 세션을 쓰므로 사용자 카트에는 아무것도 남지 않습니다.

## 동작 방식

- **수집**: 로그인 없이 정적 HTML만 받습니다. 중고샵 검색(`/product/search?domain=USED_GOODS`)으로 판본을 찾고, 판매 목록 조각(`/Product/UsedShopHub/GoodsList`)을 끝 페이지까지 읽습니다. yes24 Open API에는 중고 데이터가 없어 쓰지 않습니다
- **배송비 단위**: 예스24배송은 yes24 하나(2,500원, 15,000원 이상 무료), 매장ON은 지점마다, 판매자 배송은 판매자마다 따로 계산합니다. 배송비 문구는 아는 형태만 해석하고, 처음 보는 형태가 나오면 멈춥니다
- **최적화**: 책마다 판매 건 하나를 고르는 변수, 판매자 이용 여부와 무료배송 달성 여부를 나타내는 이진변수로 MILP를 세웁니다. 수십 권 규모는 바로 풀립니다. 작은 무작위 문제 40개로 전수탐색과 대조해 모두 일치했습니다

자세한 검토 과정·수집 경로·배송비 문구 형태·카트 구현 메모는 [docs/design-notes.md](docs/design-notes.md)에 있습니다.

## 수집 예절

yes24 `robots.txt`는 중고 허브 경로(`/Product/UsedShopHub/Hub`, `/24/UsedShop/`)를 막아 두었습니다. 그래서 이 도구는 **실제로 살 때만 한 번, 천천히** 돌리는 용도로 씁니다.

- 요청 간격은 1초 이상입니다. 10권 안팎 목록 하나에 30~50회 요청합니다
- 가격 감시나 주기 실행은 하지 않습니다
- 수집한 데이터는 개인 구매 판단에만 쓰고 재배포하지 않습니다

## 구조

```
ubc/yes24.py       수집 — 검색 → 판본 후보, 판매 목록(전 페이지), 배송비 문구 해석
ubc/optimize.py    MILP(PuLP + CBC)
ubc/cart.py        카트 대조(Playwright, 비회원 카트)
ubc/__main__.py    CLI — 목록 → 판본 → 수집 → 최적화 → (카트 대조) → 보고서
tests/             파서(저장된 HTML fixture), 최적화(전수탐색 대조)
examples/          시험용 목록과 결과
purchases/         실제 구매 건별 목록·보고서·스냅숏·카트 스크린숏
docs/              설계 노트
```

테스트: `python -m pytest tests`

## 한계와 다음 할 일

- 검색어로 넣은 책은 1순위 판본을 자동으로 고릅니다. 가끔 틀립니다(예: 코스모스 2006판과 2004판). 보고서의 판본 표를 확인하세요
- 세트 판매 건(여러 권을 한 번에 파는 건)은 아직 비교하지 않습니다
- 예스24배송 중고를 새책과 함께 살 때 무료배송 기준이 합산되는지는 확인하지 않았습니다
- yes24 페이지 구조가 바뀌면 수집이 깨집니다. 그때는 `tests/fixtures`를 새로 받아 파서를 고칩니다
